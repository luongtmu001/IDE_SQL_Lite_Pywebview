# BUG FIX & NEW FEATURE REQUIREMENTS

## I. BUG FIX

### BUG 1 — Không cập nhật DDL script mới nhất sau khi F5 Routine

#### Hiện trạng

Khi user:

1. Mở Procedure/Function.
2. Chỉnh sửa DDL.
3. Nhấn `F5` để execute/alter object.
4. Sau đó tiếp tục `ALTER` object.
5. Khi thực hiện thao tác lấy DDL script lại, IDE vẫn lấy nội dung cũ.

Hiện tại user phải vào **Explore Object → Generate Script** thì DDL mới được cập nhật.

#### Nguyên nhân nghi ngờ

Cache metadata/DDL của:

* Procedure
* Function
* View
* Trigger
* Các routine khác

chưa được invalidate/refresh sau khi `F5` thực hiện thành công

#### Yêu cầu xử lý

Sau khi `F5` thực thi thành công một câu lệnh tạo/sửa object:

* Xác định object đã được thay đổi.
* Invalidate DDL/script cache của object đó.
* Refresh metadata cần thiết.
* Lần tiếp theo khi lấy DDL phải lấy phiên bản mới nhất từ database.
* Không yêu cầu user phải thực hiện `Generate Script` thủ công để refresh cache.

#### Lưu ý

Không refresh toàn bộ database metadata nếu không cần thiết.

Ưu tiên:

```text
Execute F5
    ↓
Detect affected object
    ↓
Invalidate object cache
    ↓
Refresh object metadata/DDL
```

Nếu không thể xác định chính xác object bị ảnh hưởng, mới sử dụng cơ chế refresh rộng hơn.

# BUG 2 — Monaco Find (`Ctrl + F`) xử lý sai Enter / Shift + Enter

## Hiện trạng

Khi sử dụng `Ctrl + F`:

1. User mở Find.
2. Focus đang nằm trong ô tìm kiếm.
3. User nhấn `Enter` hoặc `Shift + Enter` để di chuyển tới kết quả tiếp theo/trước đó.
4. IDE không xử lý phím này cho Find.
5. Thay vào đó, event bị truyền xuống editor và có thể tạo newline tại vị trí cursor.

Ngoài ra, sau khi nhấn lại vào ô Find một lần nữa thì có trường hợp ô tìm kiếm không nhận input.

## Yêu cầu

Kiểm tra và xử lý keyboard event của Monaco Find Widget.

### Enter

Khi Find Widget đang focus:

```text
Enter
→ Find next
→ Không insert newline vào editor
```

### Shift + Enter

```text
Shift + Enter
→ Find previous
→ Không insert newline vào editor
```

### Event isolation

Khi Find Widget đang active:

* Keyboard event phải được xử lý bởi Find Widget.
* Không được bubble xuống editor.
* Không làm thay đổi cursor/selection ngoài hành vi Find.
* Không làm mất focus/input state.

### Cần kiểm tra thêm

* `keydown`
* `keyup`
* `keypress` nếu đang được sử dụng
* `preventDefault()`
* `stopPropagation()`
* Monaco command/keybinding
* Find Widget focus state

Đặc biệt tránh fix bằng cách chặn `Enter` toàn cục vì có thể ảnh hưởng tới editor và các component khác.

# BUG 3 — SQL Server ALTER bị Generate Script thành CREATE

## Hiện trạng

Một số trường hợp với SQL Server:

User đang viết:

```sql
ALTER PROCEDURE ...
```

hoặc:

```sql
ALTER FUNCTION ...
```

nhưng khi IDE thực hiện Generate Script/Script Object thì lại sinh thành:

```sql
CREATE PROCEDURE ...
```

## Yêu cầu

Kiểm tra logic xác định loại DDL của SQL Server object.

Phải phân biệt chính xác:

```text
CREATE
ALTER
CREATE OR ALTER
```

và object type:

```text
PROCEDURE
FUNCTION
VIEW
TRIGGER
...
```

### Nguyên tắc

Nếu database object đã tồn tại và thao tác hiện tại là sửa object thì không được tự động chuyển `ALTER` thành `CREATE` nếu không có yêu cầu rõ ràng.

Cần kiểm tra:

* Metadata object existence.
* Object type.
* DDL hiện tại trong editor.
* Logic Generate Script.
* Logic Normalize/Transform DDL.
* Cache object metadata.
* SQL Server-specific handling.

### Regression requirement

Không làm thay đổi behavior của:

```sql
CREATE ...
```

và:

```sql
CREATE OR ALTER ...
```

đang hoạt động đúng.

# BUG 4 — Generate Script bị ghi đè file trùng tên

## Hiện trạng

Khi Generate Script từ:

```text
Explore Object
    → Generate Script
```

PM đã xử lý việc lấy tên object để đặt tên file.

Ví dụ:

```text
MyProcedure.sql
```

Tuy nhiên nếu file đã tồn tại, file mới sẽ ghi đè file cũ.

## Yêu cầu

Không được overwrite file đã tồn tại.

Nếu tên file đã tồn tại thì tự động tạo hậu tố:

```text
MyProcedure.sql
MyProcedure(1).sql
MyProcedure(2).sql
MyProcedure(3).sql
...
```

### Quy tắc

Nếu:

```text
file.sql
```

đã tồn tại:

```text
file(1).sql
```

Nếu tiếp tục tồn tại:

```text
file(2).sql
```

### Phải xử lý cả trường hợp

```text
file.sql
file(1).sql
file(2).sql
file(4).sql
```

Không được đơn giản lấy số lượng file để tạo tên.

Phải tìm tên file chưa tồn tại.

### Lưu ý

Không thay đổi extension của file.

Ví dụ:

```text
procedure.sql
procedure(1).sql
```

Không phải:

```text
procedure.sql(1)
```

# BUG 5 — F5 Object làm mất vị trí cursor

## Hiện trạng

Khi user đang chỉnh sửa Procedure/Function hoặc object khác:

1. Cursor đang ở một vị trí cụ thể.
2. User nhấn `F5`.
3. Object được execute thành công.
4. IDE tự động đưa cursor về đầu file.

Điều này gây mất vị trí làm việc hiện tại.

## Yêu cầu

Sau khi `F5`:

* Giữ nguyên cursor position.
* Giữ nguyên selection nếu có.
* Giữ nguyên editor state nếu có thể.
* Không tự động scroll về đầu file.

### Nguyên tắc

Trước khi execute:

```text
Save editor state
    ↓
cursor position
selection
scroll position
```

Sau khi execute:

```text
Restore editor state
```

Chỉ thay đổi vị trí cursor nếu có lỗi hoặc một hành vi khác bắt buộc phải navigate tới error.

# II. NEW FEATURE — TAB MANAGEMENT

## Feature 1 — Di chuyển Tab

Thêm khả năng thay đổi vị trí tab.

User có thể:

* Drag & Drop tab.
* Di chuyển tab sang trái/phải.
* Thứ tự tab sau khi di chuyển phải được lưu trong state hiện tại của IDE.

### Yêu cầu

Không làm mất:

* Connection ID.
* Database context.
* Schema context.
* File association.
* Editor state.
* Pin state.

Khi tab được di chuyển chỉ thay đổi:

```text
Tab order
```

không thay đổi context của tab.

---

# Feature 2 — Keyboard Shortcut cho Tab

Cập nhật Context Menu của Tab.

Mỗi action có shortcut phải hiển thị shortcut nhỏ ở phía bên phải của menu item.

Ví dụ:

```text
New Tab                         Ctrl + N
Close Tab                      Ctrl + W
Close All Tabs          Ctrl + Shift + W
Close Tab to Right      Ctrl + W + →
```

Shortcut phải được căn phải, không làm ảnh hưởng layout của menu.

---

## 2.1 Ctrl + N — New Tab

Tạo tab mới.

### Quan trọng

Tab mới phải giữ lại các `connectionId` hiện thời của context đang active.

Ví dụ:

```text
Current Tab
Connection = Connection A
Database   = DB_A
Schema     = dbo
```

Khi:

```text
Ctrl + N
```

tab mới phải sử dụng:

```text
Connection = Connection A
Database   = DB_A
Schema     = dbo
```

Không được tự động chuyển sang connection mặc định.

---

## 2.2 Ctrl + W — Close Current Tab

Đóng tab hiện tại.

Nếu tab có nội dung chưa lưu:

```text
Show confirmation
```

Ví dụ:

```text
File has unsaved changes.
Do you want to close this tab?
```

Không được mất dữ liệu nếu user chọn Cancel.

---

## 2.3 Ctrl + Shift + W — Close All Tabs

Đóng tất cả tab.

Nếu có tab chưa lưu:

* Phải cảnh báo.
* Xử lý từng tab có unsaved changes theo yêu cầu hiện tại của hệ thống.
* Không được silently discard unsaved changes.

---

## 2.4 Ctrl + W + Right Arrow — Close Tab to Right

Đóng tab bên phải tab hiện tại.

Ví dụ:

```text
Tab A | Tab B | Tab C | Tab D
              ↑
          Current Tab
```

Thực hiện:

```text
Ctrl + W + →
```

kết quả:

```text
Tab A | Tab B
```

với các tab bên phải được đóng.

Nếu có tab chưa lưu:

* Hiển thị confirmation.
* Không được silently discard data.

### Lưu ý về shortcut

Kiểm tra khả năng conflict với browser/OS/Monaco.

Nếu tổ hợp:

```text
Ctrl + W + Right Arrow
```

không thể bind trực tiếp ổn định, xây dựng cơ chế key sequence/chord phù hợp nhưng không ảnh hưởng các shortcut hiện tại.

# Feature 3 — Tab Context Menu

Bổ sung các menu item:

```text
Pin Tab
Open in File Explorer
```

---

## 3.1 Pin Tab

Cho phép pin/unpin tab.

### Behavior

Tab được pin:

* Luôn hiển thị ở khu vực đầu danh sách tab.
* Không bị đẩy xuống phía sau khi mở tab mới.
* Giữ nguyên connection/context/editor state.

### Thứ tự Pin

Nếu pin nhiều tab:

```text
Tab A → Pin
Tab B → Pin
Tab C → Pin
```

thì thứ tự:

```text
Tab A | Tab B | Tab C | ...
```

Theo đúng thứ tự user thực hiện pin.

Không tự động sort theo:

* tên file
* tên object
* thời gian chỉnh sửa

### Khi unpin

Tab trở lại khu vực tab thông thường theo logic ordering hiện tại.

---

## 3.2 Open in File Explorer

Áp dụng cho tab/file đã được lưu trên filesystem.

Context menu:

```text
Open in File Explorer
```

Khi click:

* Mở Windows File Explorer.
* Navigate tới thư mục chứa file.
* Nếu phù hợp, có thể sử dụng cơ chế `select` file để user nhìn thấy chính xác file đang mở.

### Với file chưa được lưu

Disable menu item hoặc không thực hiện action.

Không được báo lỗi không cần thiết.

---

# Feature 4 — Taskbar → File → Open File

Thêm chức năng:

```text
Taskbar
    → File
        → Open File
```

Cho phép user mở file từ filesystem.

## File extensions hỗ trợ

```text
.sql
.xml
.txt
.csv
```

### Flow

```text
File
 ↓
Open File
 ↓
Windows File Picker
 ↓
User chọn file
 ↓
IDE mở file thành tab
```

### Yêu cầu

IDE phải xác định đúng editor dựa trên extension.

| Extension | Editor                  |
| --------- | ----------------------- |
| `.sql`    | SQL Editor              |
| `.xml`    | XML Editor              |
| `.txt`    | Text Editor             |
| `.csv`    | CSV/Text Editor phù hợp |

### Context

File mở từ filesystem phải:

* Có tab riêng.
* Giữ đường dẫn file.
* Có trạng thái modified/unsaved.
* Có thể Save.
* Có thể Save As nếu hệ thống hiện tại hỗ trợ.
* Có thể sử dụng `Open in File Explorer`.

Không được làm mất connection context của các SQL tab đang mở.

# V. ACCEPTANCE CRITERIA

## DDL

* [ ] F5 ALTER Procedure → metadata/cache được cập nhật.
* [ ] F5 ALTER Function → metadata/cache được cập nhật.
* [ ] Generate Script lấy đúng DDL mới nhất.
* [ ] Không cần Generate Script thủ công để refresh cache.

## Monaco Find

* [ ] Ctrl + F mở Find.
* [ ] Enter trong Find → Find Next.
* [ ] Shift + Enter trong Find → Find Previous.
* [ ] Không insert newline vào editor.
* [ ] Find input tiếp tục nhận keyboard input bình thường.
* [ ] Không ảnh hưởng Enter/Shift+Enter khi editor đang focus.

## SQL Server DDL

* [ ] ALTER không bị chuyển thành CREATE ngoài ý muốn.
* [ ] CREATE vẫn hoạt động.
* [ ] CREATE OR ALTER vẫn hoạt động.
* [ ] Procedure/Function/View/Trigger được xử lý đúng.

## File Generation

* [ ] Không overwrite file tồn tại.
* [ ] `file.sql` → `file(1).sql`.
* [ ] Nếu `file(1).sql` tồn tại → `file(2).sql`.
* [ ] Không thay đổi extension.

## F5

* [ ] Cursor position được giữ nguyên.
* [ ] Selection được giữ nguyên.
* [ ] Scroll position được giữ nguyên nếu có thể.
* [ ] Khi có lỗi, navigation tới error vẫn hoạt động.

## Tabs

* [ ] Có thể reorder tab.
* [ ] Pin tab.
* [ ] Unpin tab.
* [ ] Pinned tabs nằm đầu.
* [ ] Pinned tabs giữ đúng thứ tự pin.
* [ ] Ctrl + N tạo tab mới với connection context hiện tại.
* [ ] Ctrl + W đóng tab hiện tại.
* [ ] Ctrl + Shift + W đóng tất cả tab.
* [ ] Ctrl + W + Right Arrow đóng các tab bên phải.
* [ ] Các thao tác đóng tab có unsaved changes phải cảnh báo.

## File

* [ ] File → Open File hoạt động.
* [ ] Mở được `.sql`.
* [ ] Mở được `.xml`.
* [ ] Mở được `.txt`.
* [ ] Mở được `.csv`.
* [ ] Editor được chọn đúng theo extension.
* [ ] Open in File Explorer hoạt động với file đã lưu.
* [ ] Không ghi đè file khi Generate Script.

# VI. IMPORTANT IMPLEMENTATION PRINCIPLE

Không chỉ sửa triệu chứng.

Với mỗi bug, agent phải xác định:

```text
Current behavior
        ↓
Root cause
        ↓
Affected component
        ↓
Minimal fix
        ↓
Regression test
```

Ưu tiên sửa tại đúng layer gây ra vấn đề thay vì thêm workaround ở UI layer.

Đặc biệt với BUG 1 và BUG 3 cần kiểm tra mối liên hệ giữa:

```text
Database Metadata
        ↕
Object Cache
        ↕
DDL Generator
        ↕
Explore Object
        ↕
Editor
        ↕
F5 / Execute
```

Mục tiêu là đảm bảo **database là source of truth**, còn cache chỉ phục vụ hiệu năng và phải được invalidate đúng thời điểm.
